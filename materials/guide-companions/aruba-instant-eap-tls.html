Section 1 / Overview

Aruba Instant EAP-TLS 設定ガイド副読本

Aruba Instantの無線LANで、SingleIDの拡張RADIUSを使ったクライアント証明書認証を構成する際の設定意図と確認観点を整理する。

この資料の使い方

公開ガイドの画面操作を再掲せず、見出しごとに設定の意味と対応関係を読む。実際の操作と設定値は公開ガイドで確認する。

参照: https://pubdocs.singleid.jp/singleid-pocguide/aruba_instant/wlan-group-cert-adv/

このガイドで作る認証構成

接続先認証方式SingleIDの役割
Windows端末がAruba InstantのSSIDへ接続する。Aruba InstantはRADIUSクライアントとして認証要求を送る。 EAP-TLSで端末のクライアント証明書を使い、許可ユーザまたはグループを判定する。 拡張RADIUSサーバとRADIUSサイトで、NAS-Identifierにより機器を識別し、認証と任意のVLAN IDを判定する。

先に満たす前提条件

  • 公開ガイドはAP-505-JPおよびAP-615-JP、Aruba Instant 8.7.1.11、8.12.0.0、8.13.3.0で確認されている。異なる機種・版は要確認。
  • この副読本は拡張RADIUSとEAP-TLSを対象にする。パスワード認証、Aruba Central、Authentication Survivabilityの構築手順は扱わない。
  • Authentication SurvivabilityはSingleIDでは利用できない。障害時の接続継続は別途の可用性設計として判断する。

Section 2 / SingleID Identity Preparation

認証対象を準備する

認証対象のユーザと許可グループを決め、クライアント証明書を発行する。

設定ガイド見出し 1・2

グループとユーザを準備する

SingleIDで行うこと何のためか
管理者ポータル＞グループで、無線LAN接続を許可するグループを作成する。RADIUSサイトで許可対象をグループ単位で判定するため。
管理者ポータル＞ユーザで対象ユーザを登録し、無線LAN用グループへ所属させる。証明書の主体とRADIUSの許可条件を対応させるため。
ユーザが有効で、許可グループに所属していることを確認する。証明書が正しくても、ユーザ状態または許可条件で拒否されないようにするため。

設定ガイド見出し 3

クライアント証明書を発行する

SingleIDで行うこと何のためか
ユーザ一覧で対象ユーザを選択し、証明書を発行する。端末がEAP-TLS認証時に提示するクライアント証明書を用意するため。
プロファイルと配布形式を選択して発行する。用途と配布方法に合う証明書を作成するため。
発行通知とダウンロードリンクを使う場合は、利用者の受信・導入手順を確認する。端末に証明書が導入されるまでを認証準備に含めるため。

Section 3 / SingleID Authentication Foundation

認証基盤を設定する

拡張RADIUSサーバを登録し、RADIUSサイトで機器を識別して許可条件を設定する。

設定ガイド見出し 4

拡張RADIUSサーバを登録する

SingleIDで行うこと何のためか
認証＞RADIUS＞基本設定で、UDPの拡張RADIUSサーバを登録し、プライマリ／セカンダリIPアドレスと専用RADIUSポートを控える。Aruba Instantが認証要求を送る専用のRADIUS入口を作るため。
十分に複雑なシークレットを設定し、Aruba InstantのShared keyとRetype keyへ同じ値を設定する。RADIUSクライアントとサーバで同じ共有シークレットを使うため。

設定ガイド見出し 5

RADIUSサイトを登録する

SingleIDで行うこと何のためか
RADIUSの簡易設定からAruba Instant 無線LANアクセスポイントを選び、サーバに拡張を指定する。Aruba Instant用の認証・認可条件を作るため。
サイト識別する属性にNAS-Identifierを選び、任意の属性値を設定する。Aruba Instantから来た要求を、このRADIUSサイトへ対応付けるため。
許可するユーザまたはグループを登録し、証明書認証（EAP-TLS）のみ許可を有効にする。VLANを返す場合は、ユーザまたはグループごとのVLAN IDも設定する。証明書認証以外の方式を拒否し、許可範囲を限定するため。

登録後、設定が反映されるまで最大15分かかる場合がある。接続試験は反映待ちを考慮して実施する。

Section 4 / Device Configuration

機器側を設定する

SingleIDの拡張RADIUSを参照し、RADIUSサーバ、SSID、再認証を設定する。機器を識別する値はRADIUSサイトと対応付ける。

設定ガイド見出し 6

RADIUSサーバの設定

Aruba Instantで行うこと何のためか
Configuration＞Security＞Authentication Serversで、SingleIDのプライマリIP、拡張RADIUSの専用ポート、共有シークレットを使いプライマリRADIUSサーバを登録する。SingleIDへEAP-TLS認証要求を送るため。
RadSecを無効にする。公開ガイドに従い、SingleIDの拡張RADIUSへUDPで認証要求を送るため。
Timeoutを10秒に設定する。クラウドRADIUSとの通信遅延を考慮し、応答待ち時間を確保するため。
NAS-Identifierに、RADIUSサイトを一意に識別できる文字列を設定する。1つの送信値に複数サイトの属性値が一致しないようにする。SingleIDが正しいRADIUSサイトを識別するため。
セカンダリIPを使い、プライマリと同じNAS-IdentifierでセカンダリRADIUSサーバを登録する。プライマリへ送れない場合の問い合わせ先を用意するため。

設定ガイド見出し 6

SSIDと認証サーバの設定

Aruba Instantで行うこと何のためか
Configuration＞NetworksでSSIDを作成し、TypeをWireless、Primary usageをEmployeeにする。従業員向けの無線LAN接続を作るため。
Security LevelをEnterpriseにし、WPA2-EnterpriseまたはWPA3-Enterprise (CCM 128)を選ぶ。802.1X/EAP-TLSで認証するため。
Authentication server 1と2に、登録したプライマリ／セカンダリRADIUSサーバを選ぶ。SSIDの認証をSingleIDへ送るため。
EAP Offloadが無効であることを確認する。EAP-TLSをSingleIDのRADIUSサーバで処理するため。
SSIDのVLAN設定で、Client VLAN assignmentをDynamicにする。SingleIDのRADIUSサイトが返すVLAN情報に基づいて、接続先VLANを割り当てるため。

再認証と接続継続の扱い

Aruba Instantで行うこと何のためか
Reauth intervalを1440分に設定する。接続中クライアントを24時間ごとに再認証する。再認証失敗時は切断されるため、利用時間帯と端末の証明書更新・失効運用を考慮する。
Opportunistic Key Caching（OKC）を有効にする。同一Instantクラスタ内のローミング時にPMKキャッシュを利用し、対応端末で完全な802.1X認証が高頻度に起きることを抑える。
802.11r／k／vは端末対応と無線LAN運用方針に応じて設定する。無線LANのローミング動作を調整する。SingleID連携の必須設定ではない。

SSIDをCalled-Station-Idに含める

対象SSIDプロファイルのCLIで、Called-Station-IdへSSIDを含め、AP MACアドレスとSSIDの区切りにコロンを使う。認証要求にどのSSIDへの接続かを含めるための設定であり、VLANを割り当てる設定ではない。

configure terminal
wlan ssid-profile <SSIDプロファイル名>
 called-station-id type macaddr
 called-station-id include-ssid delimiter :
end
commit apply

SSIDプロファイル名と実際の設定対象は環境ごとに異なる。CLI適用前に対象SSIDを確認する。

Section 5 / Client Configuration

端末側を設定する

端末側では、EAP-TLSで提示するクライアント証明書と、接続先を検証する無線LANプロファイルを準備する。

クライアント証明書の導入

端末側で行うこと何のためか
証明書発行通知からクライアント証明書を取得する。WindowsがEAP-TLS時に提示する証明書を準備するため。
接続するWindowsユーザの証明書ストアへ証明書をインポートする。無線LAN接続時に証明書を選択できる状態にするため。
端末管理で配布する場合は、対象端末・対象ユーザ・配布失敗時の対応を決める。多数端末への導入を一貫して行うため。

SSID接続の確認

  • 対象SSIDを選択し、WindowsのEAP方式としてEAP-TLSを使用する。
  • 信頼する認証局と接続先のサーバ名の検証を、公式クライアント接続設定に従って設定する。
  • 接続したユーザと提示した証明書が、SingleIDの許可対象と一致することを確認する。

クライアント接続設定: https://pubdocs.singleid.jp/singleid-pocguide/clients/windows_setup_wlan_cert2/

Section 6 / Test And Troubleshooting

接続試験と切り分けを行う

接続可否だけで終わらせず、RADIUS認証ログ、Aruba Instant設定、端末の証明書・プロファイルを対応付けて記録する。

RADIUS認証ログは、認証実行後から表示まで5分程度かかる場合がある。直後に表示されない場合は、発生時刻とユーザ名を控えて時間を置き、再表示する。待機後も表示されない場合は、RADIUSクライアントIP、共有シークレット、宛先IP・ポート、経路を確認する。

接続試験の合格条件

確認すること合格条件
SSID接続許可ユーザとクライアント証明書で対象SSIDへ接続できる。
SingleIDのRADIUS認証ログAruba Instantからの要求と認証結果を確認できる。
VLAN割り当てVLANを設定した場合、想定したネットワークへ接続される。
再認証とローミング運用方針に応じ、再認証とAP間移動で想定外の切断がない。

失敗時の切り分け

発生状況確認すること
RADIUS認証ログがないAruba InstantのRADIUSサーバ設定、経路、UDP到達性を確認する。プライマリ／セカンダリIP、専用ポート、Shared key、Aruba InstantからSingleIDへの経路を照合する。
サイト識別で止まるSingleIDのRADIUSサイトとAruba InstantのNAS-Identifierを確認する。サイトの属性値と、プライマリ／セカンダリに設定したNAS-Identifierを照合する。
EAP-TLSで拒否されるユーザ状態、グループ、クライアント証明書、Windowsプロファイルを確認する。EAP-TLSのみ許可、許可グループ、証明書の導入先、認証局・サーバ名検証を照合する。
認証成功後に期待したネットワークへ接続しないRADIUSサイトのVLAN IDとSSIDのDynamic VLAN設定を確認する。SingleIDのVLAN設定、Client VLAN assignment、Aruba Instant側のVLAN構成を照合する。
ローミングまたは再認証で切断するReauth interval、OKC、端末対応状況を確認する。接続切断時刻とRADIUS認証ログを照合し、無線LAN運用方針に合わせて設定を見直す。

Section 7 / Summary

この副読本の読み終わりで説明できること

  • SingleID側で設定した拡張RADIUS、NAS-Identifier、許可グループが、Aruba Instant側のどの値と対応するか説明できる。
  • EAP-TLS、SSID、動的VLAN、Called-Station-Idの役割を分けて説明できる。
  • 認証失敗時に、RADIUS到達、サイト識別、証明書、認可情報を分けて確認できる。
