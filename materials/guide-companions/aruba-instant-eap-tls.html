Section 1 / Overview

Aruba Instant EAP-TLS 設定ガイド副読本

Aruba Instantの無線LANで、SingleIDの拡張RADIUSを使ったクライアント証明書認証を構成する際の設定意図と確認観点を整理する。

この資料の使い方

公開ガイドの画面操作を再掲せず、見出しごとに設定の意味と対応関係を読む。実際の操作と設定値は公開ガイドで確認する。

参照: https://pubdocs.singleid.jp/singleid-pocguide/aruba_instant/wlan-group-cert-adv/

このガイドで作る認証構成

接続先認証方式SingleIDの役割
Windows端末がAruba InstantのSSIDへ接続する。Aruba InstantはRADIUSクライアントとして認証要求を送る。 EAP-TLSで端末のクライアント証明書を使い、許可ユーザまたはグループを判定する。 拡張RADIUSサーバとRADIUSサイトで、NAS-Identifierにより機器を識別し、認証と任意のVLAN IDを判定する。

先に満たす前提条件

  • 公開ガイドはAP-505-JPおよびAP-615-JP、Aruba Instant 8.7.1.11、8.12.0.0、8.13.3.0で確認されている。異なる機種・版は要確認。
  • この副読本は拡張RADIUSとEAP-TLSを対象にする。パスワード認証、Aruba Central、Authentication Survivabilityの構築手順は扱わない。
  • Authentication SurvivabilityはSingleIDでは利用できない。障害時の接続継続は別途の可用性設計として判断する。

Section 2 / SingleID Identity Preparation

認証するユーザと証明書を準備する

EAP-TLSはクライアント証明書を使う。誰に証明書を発行し、どのグループを無線LAN接続で許可するかを先に決める。

設定ガイド見出し 1

SingleIDのグループとユーザの作成

SingleIDで行うこと何のためか設計上の注意
管理者ポータル＞グループで、無線LAN接続を許可するグループを作成する。RADIUSサイトで許可対象をグループ単位で判定するため。SSIDの用途が分かる名称にする。業務用と来訪者用など、異なる接続方針を同じグループに混在させない。
管理者ポータル＞ユーザで対象ユーザを登録し、無線LAN用グループへ所属させる。証明書の主体とRADIUSの許可条件を対応させるため。手動登録とSCIM連携を混在させず、入社・異動・退職時にグループを誰が管理するか決める。
ユーザが有効で、許可グループに所属していることを確認する。証明書が正しくても、ユーザ状態または許可条件で拒否されないようにするため。検証用ユーザだけでなく、想定する運用単位のユーザでも試験する。

設定ガイド見出し 2

SingleIDのクライアント証明書の発行

SingleIDで行うこと何のためか設計上の注意
ユーザ一覧で対象ユーザを選択し、証明書を発行する。端末がEAP-TLS認証時に提示するクライアント証明書を用意するため。発行対象と導入先端末を記録する。複数端末への導入可否は証明書配布方針と合わせる。
プロファイルと配布形式を選択して発行する。用途と配布方法に合う証明書を作成するため。Windows端末へ手動導入する場合と、端末管理で配布する場合で、配布形式と利用者案内を分ける。
発行通知とダウンロードリンクを使う場合は、利用者の受信・導入手順を確認する。端末に証明書が導入されるまでを認証準備に含めるため。通知メールとリンクの扱いは、利用者支援と再発行の運用を決めてから展開する。

Section 3 / SingleID Authentication Foundation

拡張RADIUSとRADIUSサイトを対応付ける

拡張RADIUSは専用ポートとNAS-IdentifierでAruba Instantを識別する。RADIUSサーバとRADIUSサイトは役割を分けて設定する。

設定ガイド見出し 3

SingleIDの拡張RADIUSサーバの登録

SingleIDで行うこと何のためかAruba Instantへ渡す値
認証＞RADIUS＞基本設定で、UDPの拡張RADIUSサーバを登録する。Aruba Instantが認証要求を送る専用のRADIUS入口を作るため。プライマリ／セカンダリIPアドレスと、割り当てられた専用RADIUSポート番号。
十分に複雑なシークレットを設定する。RADIUSクライアントとサーバで同じ共有シークレットを使うため。Shared keyとRetype keyへ同じ値を設定する。値は機器設定と一緒に安全に管理する。

設定ガイド見出し 4

SingleIDのRADIUSサイトの登録

SingleIDで行うこと何のためか設計上の注意
RADIUSの簡易設定からAruba Instant 無線LANアクセスポイントを選び、サーバに拡張を指定する。Aruba Instant用の認証・認可条件を作るため。選択するサーバ番号は、拡張RADIUSサーバの登録で作成したものと一致させる。
サイト識別する属性にNAS-Identifierを選び、任意の属性値を設定する。Aruba Instantから来た要求を、このRADIUSサイトへ対応付けるため。属性値はAruba Instant側のNAS-Identifierと同一にする。NAS-Identifierは部分一致で検索されるため、1つの送信値に複数サイトの属性値が一致しない命名にする。
許可するユーザまたはグループを登録し、証明書認証（EAP-TLS）のみ許可を有効にする。証明書認証以外の方式を拒否し、許可範囲を限定するため。VLANを返す場合は、この画面でユーザまたはグループごとのVLAN IDも設定する。

登録後、設定が反映されるまで最大15分かかる場合がある。接続試験は反映待ちを考慮して実施する。

Section 4 / Device Configuration

Aruba InstantのRADIUS問い合わせ先を作る

Aruba Instantのプライマリ／セカンダリRADIUSサーバは、SingleIDの同じ拡張RADIUSサーバ設定から取得した値で作る。

設定ガイド見出し 5

RADIUSサーバの設定

Aruba Instantで行うこと何のためか確認する対応値
Configuration＞Security＞Authentication ServersでプライマリRADIUSサーバを登録する。SingleIDへEAP-TLS認証要求を送るため。IP AddressはSingleIDのプライマリIP、Auth portは拡張RADIUSの専用ポート、Shared keyは共有シークレット。
RadSecを無効にし、Timeoutを10秒に設定する。公開ガイドの前提に合わせたRADIUS通信にするため。RadSec有効や短いタイムアウトが残っていないかを確認する。
NAS-IdentifierにRADIUSサイトと同じ文字列を設定する。SingleIDが正しいRADIUSサイトを識別するため。RADIUSサイトの属性値と完全に同じ文字列を使う。
同じ条件でセカンダリRADIUSサーバを登録する。プライマリへ送れない場合の問い合わせ先を用意するため。セカンダリIPを使い、NAS-Identifierはプライマリと同一にする。

値の対応を先に照合する

SingleIDAruba Instant不一致時の影響
拡張RADIUSのプライマリ／セカンダリIPと専用ポートIP AddressとAuth portRADIUS認証ログに要求が届かない。
シークレットShared key／Retype keyRADIUS通信が成立しない。
RADIUSサイトのNAS-IdentifierNAS-Identifierサイト識別で認証を判定できない。

Section 4 / Device Configuration

SSIDでEAP-TLSと認可情報を使う

SSIDはEnterprise認証にし、EAP-TLSをSingleIDで処理する。VLANやローミング設定は無線LANの運用方針に合わせて判断する。

設定ガイド見出し 6

SSIDと認証サーバの設定

Aruba Instantで行うこと何のためか設計上の注意
Configuration＞NetworksでSSIDを作成し、TypeをWireless、Primary usageをEmployeeにする。業務利用者向けの無線LAN接続を作るため。SSID名と利用対象を決め、既存SSIDとの移行や端末配布の計画に含める。
Security LevelをEnterpriseにし、WPA2-EnterpriseまたはWPA3-Enterprise (CCM 128)を選ぶ。802.1X/EAP-TLSで認証するため。端末の対応状況を確認して方式を選ぶ。混在環境の可否は対象機器・端末で要確認。
Authentication server 1と2に、登録したプライマリ／セカンダリRADIUSサーバを選ぶ。SSIDの認証をSingleIDへ送るため。RADIUSサーバをSSIDに割り当てただけでは、SingleID側の許可条件は作られない。両側を確認する。
EAP Offloadが無効であることを確認する。EAP-TLSをSingleIDのRADIUSサーバで処理するため。有効にすると、意図した認証経路にならないため無効のままにする。

再認証とローミングの扱い

項目設定の目的確認観点
Reauth interval: 1440分接続中クライアントを24時間ごとに再認証する。再認証失敗時は切断される。業務時間帯と端末の証明書更新・失効運用を考慮する。
Opportunistic Key Caching (OKC): 有効同一Instantクラスタ内のローミング時にPMKキャッシュを利用する。対応端末のローミングで完全な802.1X認証が高頻度に起きることを抑える。
802.11r／k／v無線LANのローミング動作を調整する。SingleID連携の必須設定ではない。端末対応と無線LAN運用方針により判断する。

Section 4 / Device Configuration

VLANとSSID識別を混同しない

VLAN IDは認証後の認可情報、Called-Station-Idは認証要求に含めるSSID識別情報である。設定場所と目的を分けて確認する。

RADIUS属性でVLANを割り当てる場合

設定場所行うこと理由
SingleIDのRADIUSサイト許可するユーザまたはグループへVLAN IDを設定する。RADIUS応答で対象のVLAN情報を返すため。
Aruba InstantのSSID VLANステップClient IP assignmentをNetwork assigned、Client VLAN assignmentをDynamicにする。SingleIDが返すTunnel-Type、Tunnel-Medium-Type、Tunnel-Private-Group-Idに基づくVLAN割り当てを受けるため。
Aruba InstantのVLAN Assignment Rulesこの構成では追加しない。RADIUS応答とは別の条件でAruba Instant側がVLANを割り当てる設定と混同しないため。

Called-Station-Idの設定

対象SSIDプロファイルのCLIで、Called-Station-IdへSSIDを含め、AP MACアドレスとSSIDの区切りにコロンを使う。RADIUS認証ログでSSIDを含む識別情報を確認しやすくするための設定である。

configure terminal
wlan ssid-profile <SSIDプロファイル名>
 called-station-id type macaddr
 called-station-id include-ssid delimiter :
end
commit apply

SSIDプロファイル名と実際の設定対象は環境ごとに異なる。CLI適用前に対象SSIDを確認する。

Section 5 / Client Configuration

Windows端末で証明書とSSIDを準備する

端末側では、EAP-TLSで提示するクライアント証明書と、接続先を検証する無線LANプロファイルを準備する。

クライアント証明書の導入

端末側で行うこと何のためか設計上の注意
証明書発行通知からクライアント証明書を取得する。WindowsがEAP-TLS時に提示する証明書を準備するため。利用者と端末を対応付け、証明書ファイルとパスワードを安全に扱う。
接続するWindowsユーザの証明書ストアへ証明書をインポートする。無線LAN接続時に証明書を選択できる状態にするため。別ユーザまたは別ストアへ導入すると、接続時に証明書が選べないことがある。
端末管理で配布する場合は、対象端末・対象ユーザ・配布失敗時の対応を決める。多数端末への導入を一貫して行うため。手動配布と自動配布を同じ運用単位で混在させない。

SSID接続の確認

  • 対象SSIDを選択し、WindowsのEAP方式としてEAP-TLSを使用する。
  • 信頼する認証局と接続先のサーバ名の検証を、公式クライアント接続設定に従って設定する。
  • 接続したユーザと提示した証明書が、SingleIDの許可対象と一致することを確認する。

クライアント接続設定: https://pubdocs.singleid.jp/singleid-pocguide/clients/windows_setup_wlan_cert2/

Section 6 / Test And Troubleshooting

接続試験と切り分けを一連で行う

接続可否だけで終わらせず、RADIUS認証ログ、Aruba Instant設定、端末の証明書・プロファイルを対応付けて記録する。

RADIUS認証ログは、認証実行後から表示まで5分程度かかる場合がある。直後に表示されない場合は、発生時刻とユーザ名を控えて時間を置き、再表示する。待機後も表示されない場合は、RADIUSクライアントIP、共有シークレット、宛先IP・ポート、経路を確認する。

接続試験の合格条件

確認すること合格条件記録する内容
SSID接続許可ユーザとクライアント証明書で対象SSIDへ接続できる。SSID、ユーザ、端末、証明書、接続日時。
SingleIDのRADIUS認証ログAruba Instantからの要求と認証結果を確認できる。NAS ID、SSID、認証結果、エラーメッセージ。
VLAN割り当てVLANを設定した場合、想定したネットワークへ接続される。対象ユーザ／グループ、返却VLAN ID、端末の接続先ネットワーク。
再認証とローミング運用方針に応じ、再認証とAP間移動で想定外の切断がない。Reauth interval、OKC、対象端末、試験結果。

失敗時の切り分け

段階調査対象次に確認すること
RADIUS認証ログがないAruba InstantのRADIUSサーバ設定、経路、UDP到達性プライマリ／セカンダリIP、専用ポート、Shared key、Aruba InstantからSingleIDへの経路を照合する。
サイト識別で止まるSingleIDのRADIUSサイト、Aruba InstantのNAS-Identifierサイトの属性値と、プライマリ／セカンダリに設定したNAS-Identifierが同じか確認する。
EAP-TLSで拒否されるユーザ状態、グループ、クライアント証明書、WindowsプロファイルEAP-TLSのみ許可、許可グループ、証明書の導入先、認証局・サーバ名検証を確認する。
認証成功後に期待したネットワークへ接続しないRADIUSサイトのVLAN ID、SSIDのDynamic VLAN設定SingleIDのVLAN設定、Client VLAN assignment、Aruba Instant側のVLAN構成を確認する。
ローミングまたは再認証で切断するReauth interval、OKC、端末対応状況接続切断時刻とRADIUS認証ログを照合し、無線LAN運用方針に合わせて設定を見直す。

Section 7 / Summary

この副読本の読み終わりで説明できること

  • SingleID側で設定した拡張RADIUS、NAS-Identifier、許可グループが、Aruba Instant側のどの値と対応するか説明できる。
  • EAP-TLS、SSID、動的VLAN、Called-Station-Idの役割を分けて説明できる。
  • 認証失敗時に、RADIUS到達、サイト識別、証明書、認可情報を分けて確認できる。
